# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统按站码和时刻解析、去重，能落库的写入归集表，列数不对、站码坏了或时刻已经存在的行单独列出。

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python FastAPI |
| 页面 | Vue 3，无组件库 |
| 数据库 | PostgreSQL 16 |

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3229 |
| 接口 | http://localhost:8229 |
| PostgreSQL | localhost:54429（库名 `tidetelegram`） |

## 种子数据

| 批次 | 结果 |
|------|------|
| 吴淞口 11-12 早班 | 三行都已归集 |
| 外高桥 11-12 错报 | 一行新站落库，一行时刻重复，一行站码不合法 |

报文每行四段，用竖线分开：站码、十二位时间、潮位厘米、质量旗。质量旗 A 是实测，M 是插补，B 是可疑。

## 重放未接纳报文

未接纳的行不再只是陈列，可以挑出来重新解析：

1. **待重放队列**：在未接纳详情里点「加入待重放队列」，每行可随时撤出。
2. **重放设置**：定下「要求去向」，以及重放时是否允许改行。重放进行时设置不能改。
3. **选定去向**：每行二选一——原行留在未接纳（失败后追加一次原因），或原行撤下、改由新的未接纳行代替（撤下的原行写明由第几行接替）。去向选定当天冻结，同一天不能回调。
4. **重放**：按选定去向重新解析。成功才写归集表；仍然解析失败的行一律不入库，并按去向处理。

| 记录 | 说明 |
|------|------|
| 重放列表 | 每行的结果、原行号、新行号、失败次数、去向名、重放人 |
| 未接纳详情 | 首次原因与每次重放原因逐条对照 |
| 重放去向不符 | 选定去向与重放设置要求不一致时写入 |
| 重放争用 | 同一行被两人同时认领，只完成先认领的一次，后一次记争用 |

页面在「已落库」表里给重放落下的行标「重放」，未接纳列表也会写明哪一行由重放换下。
